Quizzness — COURSE ADVENTURES & PEER SUPPORT PROTOTYPE

Open index.html directly in a browser, or use http://localhost/Quizness/
when XAMPP Apache is running. No installation or build is required.

The supplied “Business concept: Quizzness” defines the proposed product:
Learn coursework -> Play -> Receive feedback -> Work on weaknesses -> Try again.
Screened peer tutoring is available as support within that cycle.
Slogan: Quizzness Over Pleasure.

The responsive digital experience has a homepage and two supporting views:
- index.html: value proposition, sample student dashboard, course cards,
  problem, three user groups, and why-now context.
- experience.html: COMP 101 quest map, a binary-search-tree insertion
  puzzle preview with native HTML feedback, illustrative topic progress, and peer-help link.
- tutoring.html: sample eligible tutor, 15/30-minute static request previews,
  separate completed-session example, and GiveBack Wallet verification flow.

Follow the dashboard into Code Kingdom, place 20 to the left of 30,

Four assessment pages remain under “The proposal” and in the footer:
- feasibility.html: concept, evidence limits, scoped pilot and validation.
- business-model.html: primary university licensing, secondary student
  subscription, future professional tutoring, and model comparisons.
- industry.html: competitor grid, observed product directions and Five Forces.

styles.css shares layout and component rules. The site uses HTML, CSS and SVG
only, with no JavaScript. Native details/summary sections reveal placement
feedback and 15/30-minute request examples. Links connect the user journey.
No accounts, real bookings, payments, saved scores or certificates exist.

Student/tutor prototype names, courses, XP, progress, tutor eligibility, availability,
GiveBack balances and prices are illustrative. The one puzzle does not
calculate the displayed topic scores or establish mastery. Requesting help
does not mark a session completed. Pending time is excluded from approved time.
Service hours count toward institutional requirements only after formal
programme recognition and authorised verification. No agreement is claimed.

The proposed MVP is one university, two courses (Programming and Mathematics),
50–100 learners, 10 tutors and 20–30 approved games per course. These are
planning targets. Content is entered into templates and reviewed by an
approved coordinator; automatic AI game generation is not proposed.
